# 混合字幕流水线：设计与使用

## PRD：目标与边界

将本地 faster-whisper（1 个常驻 worker）与 Deepgram Nova-3（默认 1 路，最多 6 路）用于不同的视频，让识别与翻译同时进行。全部视频共享 12 路翻译名额：antigravity/gemini-3.8-flash 6 路、trae-cn/deepseek-v4.1-flash 3 路、workbuddy-vps/cn:deepseek-v4.1-flash 3 路。模型加载、下载和视频协调不占翻译线程。

保留原串行入口。新入口默认仅输出计划，`--run` 执行，`--publish` 允许发布；开发验证不启动真实批处理。凭据只从 `DEEPGRAM_API_KEY` 读取。

## Architecture：组件

- `tools/deepgram_asr.py`：固定官方 HTTPS 接口，流式文件上传，有限超时，校验英文与逐词时间戳。仅 429 自动退避重试；网络超时或 5xx 的计费结果可能不确定，保留标记，需显式允许重试。
- `tools/subtitle_recovery.py`：新增不创建线程的增量 checkpoint 会话，复用现有指纹、翻译验证与单句修复规则；旧函数保持兼容。
- `tools/hybrid_pipeline.py`：单协调器，两个独立识别执行器、一个全局翻译执行器；按视频轮转派发组，重试与修复共用翻译名额。
- `tools/hybrid_runtime.py`：英文音轨获取、本地模型复用、识别缓存、来源标识、字幕验证和禁止覆盖的发布。
- `tools/local_asr_worker.py`：常驻 CUDA/CPU 子进程，以隔离模式和 UTF-8 管道启动；每次本地识别含加载最长 600 秒，超时可终止进程，后续任务重新初始化。中断会先关闭本地子进程，再保存已发出的翻译结果。
- `tools/run_hybrid_batch.py`：参数验证、批次计划、进程锁、状态文件、执行开关。

## System design：排队与恢复

待翻译工作按约 2,500 英文字符分组，沿用原有分句边界。开始新识别前检查待处理组和在途识别的估算工作量；达到高水位 32 暂停新任务，降到低水位 8 恢复。两个已发出的识别以及一个长视频可能暂时超过水位，完成结果先落盘，不丢弃；水位不是整篇转写文件大小限制。翻译提交窗口始终不超过全局名额，未提交的组由会话惰性派发。

同一视频在一次批次中只有一个 owner；本地与云端不能重复抢到同一视频。视频失败保留该视频的识别与有效翻译 checkpoint，其他视频继续。每个 checkpoint 只由协调器写入。断点匹配包含输入、分组与模型集合身份。

全局上限指单个混合调度器中的所有视频。独立旧入口和人工测试不能靠进程内信号量自动共享额度；启动文档明确不得同时运行旧批处理。

## Tech doc：持久化与安全

新状态和缓存位于 `work/hybrid_batch/`，不覆盖旧批次状态。每个视频保存识别来源、实际模型、时长与标准化结果；原始响应不记录密钥。缓存必须经过校验才能复用；识别缓存独立于翻译模型，恢复时避免重复上传。成功字幕需保留原文、顺序、时间戳，通过现有语言与质量校验；Deepgram 结果不能写进 `.whisper.json`。

发布先写完整临时文件，再用禁止覆盖的原子链接创建最终文件；已存在目标保持不变。每个批次用独占锁阻止第二个混合调度器。失效锁需要用户检查后处理，不能自动抢锁。

## 运行方式

在将要运行命令的 Git Bash 中设置当前进程环境；隐藏输入不会把 Key 写进项目文件。没有设置时，`--run` 会在下载和上传前失败，计划模式仍可用。

```bash
read -r -s -p 'Deepgram API Key: ' DEEPGRAM_API_KEY
```

```bash
export DEEPGRAM_API_KEY
```

只查看计划：

```bash
python -I tools/run_hybrid_batch.py --ids-file work/batch_next.txt --limit 2
```

设置当前运行环境的 `DEEPGRAM_API_KEY` 后，显式执行并只暂存结果：

```bash
python -I tools/run_hybrid_batch.py --ids-file work/batch_next.txt --limit 2 --run
```

发布需再加 `--publish`。`--limit` 是本轮选择的视频数上限，包含在途任务，避免只限制发布却继续产生云端费用。默认本地 CUDA、Deepgram 1 路、翻译 6+3+3（共 12 路）。`--deepgram-workers 0` 可关闭云端；`--local-workers 0` 可只走云端。不要同时运行旧串行批处理或其他翻译入口。

## 验证结果与实际限制

- 174 个离线测试通过；包括模拟完整 CLI、两来源发布、跨视频 16 路上限及 10+6 后端分配、队列暂停恢复、失败隔离、中断保存、禁止覆盖发布，以及监控页混合状态解析。
- Python 标准库 trace 测得行覆盖率：Deepgram 88.8%、调度器 96.4%、运行时 88.1%、本地子进程 83.8%、CLI 92.8%、恢复模块 99.6%；没有测分支覆盖率。
- 真实 CUDA 子进程在 `HF_HUB_OFFLINE=1` 下连续识别同一段 82.66 秒缓存音频，首轮含启动加载 10.28 秒、第二轮 1.88 秒；同一子进程复用模型，退出后进程已结束，未写字幕。
- 此前保存的真实 Deepgram 响应已通过新适配器与运行时校验，19 个句段。词时间重叠会裁剪前一词的结束时间，保留全部文字。
- 代码、Python 和安全审查发现的问题已修复并复核。本次没有发起新的 Deepgram 请求或真实翻译请求，没有启动整批任务，也没有提交 Git。
- 当前环境尚未配置 `DEEPGRAM_API_KEY`。真实双渠道加翻译的付费联合验收尚未执行，不能把模拟并发测试当作线上吞吐保证。

识别结果和翻译断点位于新的 `work/hybrid_batch/`；不自动给旧缓存改来源标签。已有英文音频仍复用旧目录的验证下载缓存。

监控页 `tools/pipeline_server.py`（`--port 8767`，页面为 `reports/translation-pipeline.html`）在 `work/hybrid_batch/status.json` 存在时优先展示混合批次：逐视频状态、识别来源（本地 / Deepgram）、翻译活跃槽位、积压组数、准入暂停和失败原因；没有混合批次时回退到旧的 `work/whisper_batch/` 视图。

中断先停止本地子进程；已经发出的云端、翻译及下载仍可能等待各自有限超时。默认下载最多 900 秒、Deepgram 单请求超时 180 秒，翻译沿用原有限重试规则。600 秒本地期限包含首次加载，特别长的视频可能需要后续按片段调度。
